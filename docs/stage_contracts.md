# Stage Contracts

## Scene

Input: video media metadata, robot type, prompt language.

Output: `SceneStageOutput`.

Scene establishes context only. It must not output action sequences, start times, end times, or frame boundaries.

Important fields:

- `primary_view`: the spatial reference view.
- `executors`: stable execution subjects, such as `left`, `right`, `single`, `base`, or `arm`.
- `touched_objects`: objects likely manipulated by the robot.
- `background_objects`: visible non-operated objects.
- `scene_summary`: compact scene summary.

## Analysis

Input: `SceneStageOutput` plus stage media.

Output: `AnalysisStageOutput`.

Analysis outputs candidate action segments. It should reuse scene executor IDs and object IDs, and it should not produce final timestamp boundaries.

Important fields:

- `candidate_segments`: ordered candidate actions.
- `uncertain_regions`: visually unclear regions.
- `analysis_notes`: compact warnings or assumptions.

## Refinement

Input: `SceneStageOutput`, `AnalysisStageOutput`, plus higher-resolution or timestamped media.

Output: `RefinementStageOutput`.

Refinement adjusts boundaries, splits/merges/trims/removes candidates, and returns final refined segments.

Important fields:

- `refined_segments`: final temporal action segments.
- `changes`: how analysis candidates were modified.

## Final Output

The final annotation is generated by `outputs/`, not by a stage. It converts contracts into lightweight, debug, trace, or legacy-compatible views.
